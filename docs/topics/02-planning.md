# 第 2 题：内容任务规划 Agent 方案

本题是备选设计，未实现为本仓库的第二个项目。下面的费用与结果均为测试设计，不是实际运行记录。

## 用户和结果

运营人员输入主题、预算和截止时间，希望得到一份可以执行的内容活动方案。输出需要同时包含计划、步骤依赖、步骤状态、工具产物、费用合计和保存结果。没有可行方案时，说明预算或时间缺口。

请求可包含 `theme`、`budget_units`、`deadline` 和 `request_id`。缺预算或截止时间时请求补充，不默认“无限预算”或自行选日期。费用表、耗时表和素材均使用合成数据。

## 工具和模型分工

提供 `search_assets`、`generate_script`、`estimate_plan`、`save_plan` 四个工具。模型提出步骤与候选方案，估算工具按费用表计算总成本和工期。模型看到超限结果后，可以换素材、减少数量、选择较低成本工具或停止。

预算校验放在工具侧，保存时再次估算。模型不能通过修改最终说明，把 12 单位方案写成 8 单位。费用宜用整数模拟单位，避免浮点累加误差。估算成本与已实际发生的工具费用分开记录，以免失败重试漏记已消耗费用。

步骤状态使用 `pending / running / succeeded / failed / skipped`。只有依赖成功后才能执行下游步骤。生成脚本成功、保存失败时，脚本仍保留；续跑只执行失败或待执行步骤。

## 一条需要展示的决策路径

测试设计：用户预算 10 单位，初稿估算为 12。模型观察缺口为 2 后，选择一套成本 8 的方案，再估算并保存。最终材料保留两次估算及修改内容。

另一条路径可设置廉价方案仍超预算，或剩余工期不足。此时模型应返回未完成，保留已经检索和生成的结果，不能为了完成而改预算、改截止时间。

## 验收设计

| 场景 | 应核对的结果 |
| --- | --- |
| 正常完成 | 成本不超预算，截止前可完成，方案实际保存 |
| 缺预算或截止时间 | 返回缺失字段，不能悄悄补值 |
| 工具失败 | 失败步骤标失败，成功步骤和产物仍存在 |
| 预算超限 | 模型看到估算后调整，再估算；无解则说明缺口 |
| 重复执行 | 同一请求不重复保存，不重复执行已有成功产物 |
| 失败续跑 | 恢复原状态，只运行失败步骤及其必要下游 |

评估时要把成本表换一组，再看模型是否仍机械选择原方案。重复执行还要核对工具实际调用次数，单看最终只有一份文件，不能证明没有重复扣费。

## 主要取舍

建议先做单进程 CLI 和本地状态文件，优先实现超预算后的真实重规划。失败续跑作为明确扩展，避免在没有稳定步骤状态前加入复杂工作流框架。时间估算先按依赖路径计算，不能把并行步骤的工期简单相加。
