# 第 4 题：短视频脚本 Agent 方案

本题是备选设计，未实现脚本生成或实际时长检查。下面的 38 秒、28 秒仅用于说明预期测试路径。

## 用户和结果

创作者输入主题、受众、平台、目标时长和风格，希望得到可继续修改的脚本。输出包含标题、分镜、画面说明、旁白或字幕、估算时长、素材来源 ID、规则风险和任务状态。

缺主题、目标时长等必要信息时先补充。风格可允许有明确记录的默认值，但不能默认一个产品功能。产品事实只能来自读取到的资料。

## 工具如何设计

`search_materials` 返回带来源 ID 的产品资料。`estimate_duration` 按旁白长度、语速和镜头最低停留时间估算时长，并列出各镜头贡献。`check_rules` 检查品牌禁用词、数值声明和来源关联。

脚本由模型生成，时长由工具算。工具返回超时长或规则风险后，模型根据具体问题修改，再次检查。只有最新稿件的检查通过，才输出完成。修改之后必须使旧检查失效，不能拿初稿的结果给新稿背书。

时长估算不等于真实配音时长，需要在输出中说明。镜头并行显示字幕和旁白时，不能把二者时长重复相加；每个镜头取必要停留时间与旁白时长中的较大值，再累计。

## 动态路径如何展示

测试设计：产品资料 P01 只写“支持字幕”。用户要 30 秒脚本，初稿估算 38 秒。模型看到超出 8 秒后，删减重复表达和非必要镜头，再估算；若为 28 秒且规则通过，可输出完成。

生成中不得出现资料没有提供的“效率提升 80%”。若首稿出现该说法，规则工具应指出缺少数值依据，模型删除或请求资料，不能自行补一个来源 ID。

检索无结果时，模型可以改写查询。第二次仍无资料则请求用户补充，保留缺口。工具失败时标明哪项未验证，不能把未检查的稿件记为完成。

## 建议文件及职责

| 文件 | 职责 |
| --- | --- |
| `src/agent.js` | 模型循环、修稿次数和总动作上限 |
| `src/providers.js` | 模型接入与离线替身 |
| `src/script-schema.js` | 标题、镜头、旁白、来源和版本格式 |
| `src/tools/search.js` | 检索产品事实与素材 ID |
| `src/tools/duration.js` | 逐镜头估算，输出总时长及超出量 |
| `src/tools/rules.js` | 检查品牌规则、数值依据和素材来源 |
| `src/check-state.js` | 检查结果绑定稿件哈希，改稿后要求复查 |
| `data/products.json` | 合成产品事实及来源 ID |
| `data/brand-rules.json` | 禁用表达、需依据的声明和格式要求 |
| `tests/script.test.js` | 缺信息、无资料、工具失败、超时修正、事实约束 |
| `examples/` | 输入、每版稿件、实际检查结果和 Trace |
| `docs/01` 至 `docs/05` | 统一交付文档 |

## 验收设计

| 场景 | 应核对的结果 |
| --- | --- |
| 正常生成 | 分镜完整、来源有效、时长与规则检查通过 |
| 缺关键信息 | 指出具体缺项，不编目标时长或产品事实 |
| 无素材 | 模型改写查询或请求补充，仍无依据则停止 |
| 工具失败 | 返回未完成，保留草稿及未验证事项 |
| 超时长 | 初稿与修订稿均有实际估算，最终通过或明确失败 |

评审还应改变目标时长和 P01 内容，核对模型的下一步及最终脚本是否随之变化。分镜来源逐项检查，不能只在结尾统一写一个 P01 就认为所有声明都有依据。

## 主要取舍

首版用明确的语速公式，便于检查压缩前后的变化，不接真实配音。规则检查先做确定规则与来源 ID 校验；复杂的语义支持关系应增加人工核对样本。优先保留稿件版本和检查结果，再考虑剪辑软件接入。
